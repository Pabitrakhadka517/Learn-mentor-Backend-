# Study Resources Module\n\nA comprehensive study material library system implementing Clean Architecture principles for the tutoring platform backend.\n\n## Overview\n\nThis module allows:\n- **Tutors/Admins**: Upload, manage, and delete educational resources\n- **Students**: Browse and access public study materials\n- **File Management**: Secure cloud storage with Cloudinary integration\n- **Content Filtering**: Category-based and search functionality\n- **Access Control**: Role-based permissions with ownership validation\n\n## Architecture\n\nFollows Clean Architecture with clear separation of concerns:\n\n```\nsrc/modules/study/\n├── domain/                     # Core business rules\n│   ├── entities/              # StudyResourceEntity with validation\n│   └── interfaces/            # Repository contracts\n├── application/               # Business use cases\n│   ├── use-cases/            # Business logic implementation\n│   └── dto/                  # Data transfer objects\n├── infrastructure/           # External concerns\n│   ├── repositories/        # MongoDB implementation\n│   ├── models/              # Mongoose schemas\n│   └── cloudinary/          # File storage service\n├── presentation/            # HTTP layer\n│   ├── study.controller.ts  # Request/response handling\n│   └── study.routes.ts      # Route definitions\n└── study.module.ts         # Dependency injection setup\n```\n\n## Features\n\n### File Upload & Management\n- **Supported Formats**: PDF, DOC, DOCX, TXT, PPT, PPTX, JPG, PNG, GIF\n- **Size Limits**: 10MB for PDFs, 5MB for other files\n- **Cloud Storage**: Secure Cloudinary integration with auto-optimization\n- **Validation**: MIME type and file size validation\n\n### Access Control\n- **Public Resources**: Accessible by all users (students, tutors)\n- **Private Resources**: Only accessible by the resource owner\n- **Role-Based Actions**:\n  - Students: View public resources only\n  - Tutors: Full CRUD operations on their own resources\n  - Admins: Full access to all resources\n\n### Search & Filtering\n- **Category Filter**: Filter by resource category\n- **Type Filter**: Filter by resource type (PDF, MODULE, OTHER)\n- **Text Search**: Search in titles and categories\n- **Sorting**: Newest first by default\n\n## API Endpoints\n\n### Public Endpoints\n```http\nGET /api/study                # Get public resources with filters\n  ?category=mathematics       # Filter by category\n  &type=PDF                  # Filter by type\n  &search=algebra            # Search in title/category\n```\n\n### Protected Endpoints (Tutor/Admin)\n```http\nGET /api/study/my            # Get my resources + statistics\nPOST /api/study/upload       # Upload new resource\nDELETE /api/study/:id        # Delete specific resource\nPOST /api/study/batch-delete # Delete multiple resources\n```\n\n## Integration Guide\n\n### 1. Environment Variables\n\nAdd to your `.env` file:\n```env\n# Cloudinary Configuration\nCLOUDINARY_CLOUD_NAME=your_cloud_name\nCLOUDINARY_API_KEY=your_api_key\nCLOUDINARY_API_SECRET=your_api_secret\n```\n\n### 2. Database Setup\n\nThe module uses MongoDB with Mongoose. The schema will be automatically created when the module initializes.\n\n**Indexes Created**:\n- `{ tutorId: 1, createdAt: -1 }` - For tutor resource queries\n- `{ isPublic: 1, category: 1, createdAt: -1 }` - For public resource filtering\n- `{ isPublic: 1, type: 1, createdAt: -1 }` - For type-based filtering\n- `{ title: 'text', category: 'text' }` - For text search\n\n### 3. App Integration\n\nAdd to your main app file (e.g., `src/app.ts`):\n\n```typescript\nimport { createStudyModule } from './modules/study/study.module';\n\n// Create study module\nconst studyModule = createStudyModule();\n\n// Add routes to app\napp.use('/api/study', studyModule.getRouter());\n\n// Optional: Health check endpoint\napp.get('/api/health/study', async (req, res) => {\n  const health = await studyModule.healthCheck();\n  res.status(health.status === 'healthy' ? 200 : 503).json(health);\n});\n```\n\n### 4.
